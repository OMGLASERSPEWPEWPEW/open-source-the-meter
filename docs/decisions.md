- 2026-11-14 · maintainer · How many yeses does setting up the meter take? → One per item on the change list; writes inside the clone while building count as one item, and every change outside the clone is its own item, because outside the clone is where a person's setup can break.
- 2026-11-14 · maintainer · Where do config backups go? → A dated copy in the meter's home, because one folder then holds every backup and client config folders get no stray files.
- 2026-11-14 · maintainer · Edit a client's config file directly, or use the client's own command? → The client's command where it has one, still backing up the file it writes, because it's the client's supported path and the agent doesn't have to parse files that hold account data.

- 2026-11-14 · maintainer · Wire the reference or build a meter by default? → The reference when python3 3.9 or later is present; a build only when the person asks or there's no such Python, because the reference already passes the vectors and needs no install.
- 2026-11-14 · maintainer · Change Claude Code's transcript cleanup setting so history lasts longer? → No: the agent may mention it and changes it only as its own item with a yes, because the meter's ledger keeps history anyway.
- 2026-11-14 · maintainer · Price old events at the prices of their day, or all events at one list? → One current list for all of history, because weeks then compare at the same prices and a change in the ceiling can only come from the plan (prices.json says the same).
- 2026-11-14 · maintainer · A local price override file outside the clone? → None in this version; the person edits the clone's prices.json, because one file is easier to audit and to date.
- 2026-11-14 · maintainer · How are models with no price handled? → Kept with their tokens, shown as unpriced, and totals and ceilings marked incomplete; never priced as zero or as a "nearest" model, because a guessed price is a wrong number that looks right.
- 2026-11-14 · maintainer · (superseded by a later line) What role does Claude Code's own cost estimate play? → A cross-check shown in status next to the meter's figure, never in a total or a ceiling, because it's Claude Code's estimate, not the meter's rule.
- 2026-11-14 · maintainer · Record a reading on every statusline redraw? → Only when the percent or the reset time changed, because the statusline redraws constantly and repeats add nothing.
- 2026-11-14 · maintainer · Should the statusline wrapper sync the logs? → No, it only appends to quota.jsonl, because it runs on every redraw and must stay fast and never wait on the ledger.
- 2026-11-14 · maintainer · (superseded by a later line) Ceilings for the five-hour window too? → Record five-hour readings but work out ceilings for the weekly window only, because the ask is week over week.
- 2026-11-14 · maintainer · (superseded by a later line) Which reading stands for a week? → Its latest firm reading, else its latest reading marked not firm, because the latest has the most spend behind it and the least rounding error.
- 2026-11-14 · maintainer · What happens when two windows of one product overlap (an early reset, or two accounts)? → Show both and flag the overlap, never merge them, because the meter can't tell which of the two it is.
- 2026-11-14 · maintainer · A command to edit or delete readings? → None in this version: the person edits quota.jsonl by hand and the ledger follows the file, because it's a plain file they own.
- 2026-11-14 · maintainer · Does Level 2's OpenTelemetry mean the meter sends data? → No: Level 2 is the clients' own export to the org's own collector, set up from docs/level-2.md, because "nothing leaves the machine" holds for the meter at every level.
- 2026-11-14 · maintainer · (superseded by a later line) Should git yield detect reverts or grade code? → No: commits and lines added and removed, minus the paths SPEC.md leaves out, because git can show counts but not quality.
- 2026-11-14 · maintainer · List meter_yield only once Level 2 is set up? → Always list it, because it needs only git and the ledger.
- 2026-11-14 · maintainer · What may the dashboard do? → A read-only page, in the foreground, on 127.0.0.1 only even by flag, with no outside assets and a Host check, because write actions or outside assets on a local page are attack surface for nothing.
- 2026-11-14 · maintainer · Must a hand-built meter offer every CLI command? → It must offer conformance and should offer the rest under the same names, because the runner needs the first and docs/install.md stays the same with the rest.
- 2026-11-14 · maintainer · (superseded by a later line) What if a client calls the meter first on a long history? → A time budget per sync with partial figures marked as catching up, and the agent runs the first sync from the CLI before wiring, because client tool calls can time out.
- 2026-11-14 · maintainer · (superseded by a later line) What does errors.log hold? → When, what, the file and the byte offset, never the line itself, because log lines hold prompt text.
- 2026-11-14 · maintainer · Can two implementations share one meter home? → Yes, through one layout defined in SPEC.md with a schema version, and a meter that finds an unknown version refuses to write, because two meters writing one ledger differently would corrupt it.
- 2026-11-14 · maintainer · Pair a Claude reading with Codex spend, or the other way? → Never; each product's readings pair only with its own spend, because each plan's percent counts only its own product.
- 2026-11-14 · maintainer · (superseded by a later line) Which settings does statusline-install change? → Claude Code's user settings only, because the wrapper should see every project; a project's own statusline wins there, and status shows the gap in readings.
- 2026-11-14 · maintainer · A UI section in the PRD? → A short one that fixes what every surface shows and in what order, with no layout design, because the dashboard is optional and its look is the builder's choice.
- 2026-11-14 · maintainer · Windows support? → Not blocked, not tested, and the docs say untested, because nobody can test it here.
- 2026-11-14 · maintainer · Name local tools from the author's own machine as prior art in the PRD? → No; it names only the public alternatives (ccusage, claumon), because the PRD ships in a public repo.
- 2026-11-14 · maintainer · Claude Code's own cost estimate as a cross-check in status (line 16)? → Withdrawn (FR-19): the reference doesn't capture it, because capturing it means writing on every statusline redraw for a number that is Claude Code's estimate, not a rule anyone can test; docs/qa.md's live check compares totals by eye instead.
- 2026-11-14 · maintainer · Ceilings for the five-hour window (line 19)? → Computed for both windows, weekly by default, because the same rule costs nothing extra and the five-hour figure answers "how much is one block worth" for people who hit that limit first.
- 2026-11-14 · maintainer · Which reading stands for a window (line 20)? → The latest reading, a tie going to the higher percent, because the percent only rises within a window, so the latest is firm whenever any is.
- 2026-11-14 · maintainer · Detect reverts in git yield (line 24)? → Yes, by exact subject only: `Revert "<X>"` pairs with a commit whose subject is X, and both are left out, because a commit and its revert cancel and leaving them in rewards churn; nothing fuzzier.
- 2026-11-14 · maintainer · A time budget per sync with "catching up" marks (line 28)? → No: the first sync runs from the CLI before the MCP server is wired (AGENTS.md step 5), and later syncs read only new bytes (well under a second on 8 GB of history), because a budget adds partial answers every implementation would have to reproduce.
- 2026-11-14 · maintainer · One machine, several Claude accounts? → Readings and events carry the account (session-owner lines, then the session, then the machine's only account); ceilings are per account and spend with no known account is reported as unattributed, because the first live run mixed two accounts' weeks into nonsense (ADR 0004).
- 2026-11-14 · maintainer · Use the transcript's "rejected" quotaLimits line? → Yes, as a 100% reading at that moment, because it's exact, free, and needs no wrapper.
- 2026-11-14 · maintainer · How wide is the band, and when is a reading firm? → Plus or minus one point on the percent; firm at 20% or more, because the plan shows whole numbers and under 20% one point moves the ceiling by more than 5%.
- 2026-11-14 · maintainer · Show a week-over-week change when windows overlap or spend is unattributed? → No change, with a note saying why, because a number there would be wrong in a way that looks right.
- 2026-11-14 · maintainer · How does the ledger follow hand edits to quota.jsonl? → Whenever its size or modification time changes it's read again whole and its readings replace the old ones, because the file is small and a delete must take effect.
- 2026-11-14 · maintainer · Which account does a manual reading belong to? → The account of that product's most recent request, because the person records what the screen shows for the account they're using.
- 2026-11-14 · maintainer · Which shell runs the person's original statusline, and with a timeout? → /bin/sh -c, no timeout of the wrapper's own, because the wrapper must behave exactly like the line it wraps; a command that needs another shell names it.
- 2026-11-14 · maintainer · Copy the reference into ~/.open-meter/app so a git pull can't change what runs (security review)? → No: the MCP server and wrapper run the audited clone with absolute paths and -I, and AGENTS.md treats any pull as a new audit, because a second copy is one more thing to keep in step and to undo.
- 2026-11-14 · maintainer · A secret path token for the dashboard (security review)? → No: 127.0.0.1 only, a Host check, a Sec-Fetch-Site check, GET only, no scripts, because the page is read-only and those checks already stop rebinding and cross-site reads.
- 2026-11-14 · maintainer · What does conformance's --codex-dir point at? → A Codex home; the meter reads its sessions/ and archived_sessions/ only, because the home also holds history.jsonl (the person's prompts), which the meter never reads.
- 2026-11-14 · maintainer · A model the price list doesn't have yet? → Unpriced and named in every report until the price list gets its row from the provider's page, because SPEC.md never guesses a price.
- 2026-11-14 · maintainer · Is the Codex ceiling a lower bound too? → Yes, and every Codex ceiling says so, because Codex's percent also counts use on other machines and in the cloud that this machine's rollouts don't hold.
- 2026-11-14 · maintainer · A response's lines disagree on its output count (review M2: 1,289 of 143,870 multi-line responses here)? → Keep the largest of each token count for the key, because a streamed response's first line can carry a partial count and the largest doesn't depend on read order.
- 2026-11-14 · maintainer · A reading with no known account on a machine with several accounts (review H3)? → Its spend counts only events with no account, known-account spend is reported as unattributed, and its change note is "account unknown", because pooling accounts is the error ADR 0004 exists to stop.
- 2026-11-14 · maintainer · The statusline command when the clone or Python moves (review M3)? → It checks both and falls back to `exec /bin/sh -c` the original, because a moved folder must never blank the person's status line.
- 2026-11-14 · maintainer · Cursor and Claude Desktop MCP setup (review M5)? → A meter command (mcp-install) that changes one entry and prints only that entry, because an AI that opens those files to edit them sends the other tools' keys to its provider.
- 2026-11-14 · maintainer · Updating the clone (review H5)? → git fetch, git diff HEAD origin/main, audit, then git merge --ff-only, because the MCP server and the status line run the clone's files and a pull would change what runs before an audit.
- 2026-11-14 · maintainer · Make the wrapper faster on macOS's Python 3.9 (review L9)? → Lazy imports only: about 125 ms there (47 ms is Python starting) and 36 ms on 3.11, because a smaller wrapper would mean a second code path to keep in step.
- 2026-11-14 · maintainer · Left for later from the review: fingerprinting rewritten logs, streaming git output with a kill, a fixed PATH for git, grouping readings by closeness instead of fixed buckets, a process-group kill in the vector runner, refusing a --db that is another program's SQLite file, prices for older Codex models (the patterns price list has no rows for them; they show as unpriced).
- 2026-11-14 · maintainer · What does errors.log hold? → Only the statusline wrapper's failures, as the error's kind, never the input; a sync counts bad lines instead of logging them, because a per-line log would grow with every bad transcript line and offsets alone help no one.

- 2026-11-14 · maintainer · Which repos may meter_yield read? → Only a folder where a Claude Code or Codex session ran (by the ledger), because elsewhere there's no spend to measure and the git call should have as few targets as possible.

- 2026-11-14 · maintainer · Which change note comes first? → "account unknown", before "first window", because on a machine with several accounts an unknown-account row can never be compared, first or not.
- 2026-11-14 · maintainer · Which Python goes into configs on macOS? → /usr/bin/python3 when the install ran from the Xcode or Command Line Tools path, because that path moves when Xcode does and the status line would quietly stop recording.
